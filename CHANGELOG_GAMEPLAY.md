# 2.9.4 (latest)
- ???
- Triggers are read by a stricter grammar when they load or are saved in trigedit. A script whose `if`, `while` and `switch` blocks don't fit together, or which has text after `else`, `end`, `done`, `break` or `default` on the same line, is refused: it stays attached but never runs, its errors are logged with line numbers when it loads, and trigedit lists them when it is saved; fixing it there makes it run. Before, such scripts ran by guesswork, often skipping to their last line. 39 triggers in the game are refused: 48, 50, 68, 451, 488, 1412, 1510, 2303, 2306, 2398, 2803, 6040, 7617, 9110, 10901, 13002, 13005, 15100, 15709, 15939, 16305, 16403, 17514, 17995, 18601, 19204, 19205–19209, 19700, 19704, 62606, 62607, 62992, 62998, 64703 and 64704, and in the repo's own world also 1137 and 2313 (`tools/dg_strict.py` gives each one's lines and reasons). The first time a refused trigger would have run, the log says so, once. [Volund]
- In a script, `if(`, `elseif(`, `while(` and `switch(` now open their blocks like `if ` does, where the old engine ran `if(` as a command and took `elseif(` for a plain `else`. This fixes triggers 17521 (the colonist no longer greets everyone as his trusted apprentice) and 19365 (the Nazrin guard no longer turns everyone away as though they had finished the maze). [Volund]
- In a script's `switch`, a case that falls through into `default` carries on past it, rather than running `default` as a command. [Volund]
- A script whose `wait` has a time it can't read (`wait until x`, or a variable holding no number) logs an error and ends, rather than waiting a random time, or, for an empty one, never running again until a reboot. A `wait` whose time is written out wrong is refused when the trigger loads. [Volund]
- A script working out text that ends in a quote and a backslash, such as something a player said, no longer reads past the end of it into whatever memory follows. [Volund]
- A script message (`msend`, `wsend`, `oecho` and the like) naming more people or things than fit in its buffer no longer overruns it: a long line of `~` or `|`, which can come from something a player said, wrote past the end of a 64KB buffer on the stack. [Volund]
- Saving a trigger in trigedit no longer cancels its copies that are waiting partway through, with their variables: the next run of each copy uses the new script, and a run that is going or waiting finishes on the script it started. [Volund]
- `tstat` lists a trigger's live copies: each one's id, what it is on, and whether it is idle, running or waiting; for one waiting, the line it carries on at, the blocks it is inside, and whether it is on the script from before the last save. It lists the script's errors too, if it has any. [Volund]
- New builder command `tcheck` lists every trigger whose script does not compile, and so never runs, with its first error; `tcheck <vnum>` lists all of one trigger's errors with their line numbers. [Volund]
- Script errors say where they happened: the trigger, its instance, the line's number and text, what it ran on and who set it off. [Volund]
- Looking at an object given a trigger in play (by a script's `attach`, say), with room flags showing, no longer crashes the game when the object's prototype has no triggers of its own. [Volund]
- A script on an object or a room asking a mob's globals for `self` (`%mob.global(self)%`) gets its own id, rather than reading the object or room as though it were a mob. [Volund]
- Creating a character makes its rolls and gains at the end, once the traits are chosen, rather than as each question is answered: the size, the base stats and abilities, the answers' gains, the age, the alignment chosen and its penalty, forgotten skills and the genomes' bonuses. A character comes out as before, but a bad answer to the first question no longer rolls the stats again, and a mutant's second mutation is rolled before the rest. [Volund]
- Logging in to a character whose player file is marked deleted starts a new one, as it's meant to, rather than reading the freed old character and then leaving the new one out of the player index and not properly in the game. [Volund]
- A number past the end of the negative traits menu (38 to 51) is refused as not an option, rather than reading and writing past the end of the character's traits. [Volund]
- Focusing a curse on yourself curses you, rather than crashing the game. [Volund]
- Carried ice that melts away no longer leaves its carrier counting less weight than they carry. [Volund]
- The top lists load all 25 places and no further: loading them no longer replaced the top powerlevel with a garbage number and disturbed the auction, and "toplist" no longer wrote past its own list. A short top list file leaves its missing places empty. [Volund]
- An immortal listing exits beside a door with no keyword is told of the error, rather than crashing the game. [Volund]
- Struggling to escape a grapple or an absorption, and knocking out or killing whoever held you, no longer crashes the game. [Volund]
- A forgery is weighed before it's handed over, so its forger no longer counts a different weight than they carry. [Volund]
- A mob made to restring something at the restring shop is ignored, rather than crashing the game. [Volund]
- Locking someone out while the lockout list holds 500 or more names no longer crashes the game. [Volund]
- Checking a zone with `zcheck` no longer crashes the game when one of its rooms has no description, or one of its mobs has no keywords, short or long description. [Volund]
- Asking for help at an OLC prompt whose context help entry has no text, such as the script editor's "delete a trigger" prompt, says there is no help for it, rather than crashing the game. [Volund]
- **Deploying:** `etc/hcontrol` and `etc/plrmail` are now text files. The first boot of this version converts the old binary ones and keeps them as `etc/hcontrol.bak` and `etc/plrmail.bak`, logging "Converted etc/hcontrol from the old binary format (N houses)" and the same for the mail. Boots after that read the text. [Volund]
- Letters are received in the order they were sent, across reboots too; the old mail file could hand a later letter over first after a reboot, if it had been stored in the place of one already read. [Volund]
- A letter whose chain of blocks in the old mail file was broken (one in the live data, to player 15207) keeps the part that could be read when the file is converted, and the log says so; receiving it would have hung or crashed the game. [Volund]
- A rent file cut short partway through an object's strings is refused when the player logs in, or listed as far as it goes, rather than shutting the game down. [Volund]
- A house file with more spellbook pages for an object than a spellbook holds no longer writes past the end of it, and an object in a house file marked as worn no longer reads before the start of the loader's lists. [Volund]
- A player file that ends partway through its description is refused, with the file and line in the log, rather than shutting the game down when the player logs in. [Volund]
- When aedit can't write the socials file, the socials stay listed as unsaved, rather than the game shutting down. [Volund]
- A help file line that starts with a NUL byte is read as an empty line, rather than writing before the reader's buffer. [Volund]
- Sensing someone new when your sense memory already holds more than 500 people no longer writes past the end of the list it was read into, which could crash the game. [Volund]
- In oedit, a feat apply whose feat is named by something that is no feat no longer reads past the end of the feat list (which could crash the game). [Volund]
- In hsedit, deleting a guest from a full guest list no longer reads past the end of the list, which left the house's last payment date in the empty place as a guest's id. [Volund]
- Creating a zone with `zedit new` no longer moves the zone of another builder's open editor to the memory after it, when that zone happened to lie after the new one in memory: leftover renumbering from when zones were kept in an array, which could make the editor show garbage, or crash the game. [Volund]
- Moving up the RPP top list when your account is listed twice in its bottom places no longer reads past the end of the list of places, which could crash the game; the last place is left empty. [Volund]
