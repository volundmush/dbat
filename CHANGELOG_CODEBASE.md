# 2.9.4 (latest)
- There was a rollback to C23 with optional Zig 0.17 support. Gameplay changes were ported. [Volund]
- Split `CHANGELOG.md` into `CHANGELOG_CODEBASE.md` and `CHANGELOG_GAMEPLAY.md`
- Removed Zig from the build. CMake now builds everything as C++26 (`-std=gnu++26`) with GCC 16; the fuzz preset still uses Clang, for libFuzzer. [Volund]
- Renamed every source file from `.c` to `.cpp`, and wrapped every header in `extern "C"` so symbols stay unmangled. [Volund]
- Headers are now C++: renamed from `.h` to `.hpp`, with all `extern "C"` wrapping removed, so the game's symbols use C++ linkage. [Volund]
- Stricter compiler warnings for C++ (format, sign-compare, cast-qual, cast-align, fall-through, pedantic and others), with `-Werror` in the debug and asan presets. Added `tools/analyze.sh` for GCC's static analyzer. [Volund]
- Every struct field has a default member initializer, and `CREATE`/`RECREATE` are gone: the game allocates with `new`/`delete`, and grows arrays with `resize_array()` (`dbat/arrays.hpp`). [Volund]
- Loops over characters, objects, connections, room contents, inventories and followers go through `dbat/iterate.hpp` (`for (char_data *ch : room_people(g, room))`, or closures such as `char_iter_all`). Each loop sees the members as they were when it began and passes over any destroyed or moved before their turn, so scripts that purge things mid-loop are safe. `world_audit` checks that every character and object can be found by its id, which this relies on. [Volund]
- Characters and objects refer to each other by id rather than by pointer (fighting, master, blocks, grappling, absorbing, defending, dragging, mind links, poisoners, seats, users, targets, walls, posts, carrying players, the summoned dragon, the object being restrung or iedited). The getters take the `GameWorld` and return null once the other entity has gone, where a pointer would have dangled. [Volund]
- Shops, guilds and zones are kept in `vnum_table`s (`dbat/registry.hpp`): owned, never moving, in vnum order, so a room or editor can hold a pointer to its zone. `shop_rnum`, `guild_rnum` and `zone_rnum` are gone, and with them the `top_*` counters and the OLC code that renumbered tables on insert. [Volund]
- Rooms and the mob, object and trigger prototypes are `vnum_table`s too, and every rnum type is gone: a room, prototype or trigger is found by its vnum (`room_of`, `obj_proto_of`, `mob_proto_of`), a character's `in_room` and an object's `item_number` hold vnums. `real_room()`, `real_object()` and `real_mobile()` are deleted, since `room_of`, `obj_proto_of` and `mob_proto_of` already say whether a vnum is in use. OLC no longer shifts tables, exits, zone commands, start rooms or occupants when a room or prototype is added or deleted, and deleting an object prototype also takes it out of shop stock lists. Waiting room triggers no longer need re-pointing, since rooms never move. [Volund]
- The accessors that take a room's vnum (`room_get_name(g, vnum)` and the rest, formerly `rroom_*`) are overloads of the ones that take the room, and are safe on a vnum with no room: getters give nothing and setters do nothing, so `NOWHERE` is simply a vnum no room has. `read_object()` and `read_mobile()` no longer take `REAL`/`VIRTUAL`. [Volund]
- Characters and objects are registered by id in `id_table`s (`g->characters`, `g->objects`), which replace both the `next`-linked global lists and DG's UID hash: being in the game and being findable by id are now one thing. `char_register()`/`obj_register()` and their `unregister` partners replace `add_to_lookup_table()`/`remove_from_lookup_table()`; unregistering removes only the entity registered under that id, so freeing a copy of a character (one loaded from a player file, say) no longer makes the real one unfindable. A player who returns to the menu is unregistered until they enter the game again. [Volund]
- Connections (`g->descriptors`, by `desc_num`) and attached triggers (`g->triggers`, by a serial id) are `id_table`s too, replacing the `next`/`next_in_world` lists; triggers waiting to be freed are a `std::vector`. Connection numbers still wrap at 1000, but skip any still in use. [Volund]
- Extracted objects are freed between pulses: `extract_obj()` takes the object out of the game at once (no longer found by id, unique id, or any loop), but its memory lasts until `finish_extractions()` (formerly `extract_pending_chars()`), so a pointer held across a trigger or a purge reads a dead object rather than freed memory. OLC frees the waiting copies of a prototype before it changes or deletes it, since they share its strings. Characters were already freed this way. [Volund]
- A room's people and contents, an inventory and a container's contents are `id_list`s of member ids, newest first as the linked lists were, replacing `next_in_room`/`next_content`. The getters return the list; functions that took a list head (`get_obj_in_list_vis()` and the rest) take one; `first_obj()`/`first_char()`, `obj_list_from()`, `obj_next_in_list()` and `char_next_in_room()` (`dbat/iterate.hpp`) cover what following the links did, including DG's `next_in_list` and `next_in_room`. Only registered entities can be listed, and placing one that isn't logs a SYSERR; players are registered before they enter their room. The audit checks that no list names a member twice or one that is gone. [Volund]
- Followers are an `id_list` too, replacing `struct follow_type`. The combat and affect lists are `id_table`s (`g->combat_list`, `g->affect_list`), replacing `next_fighting`/`next_affect` and the `next_combat_list` save-next pointer; `each_fighting()` and `each_affected()` loop over them, passing over anyone who leaves before their turn. `free_char()` takes a character out of both. [Volund]
- A character's own lists are C++ containers: skills are a `std::map` holding only those with something set (read through the same accessors, so an unset one is still 0); affects are a `std::list<affected_type>` (`char_affects()`), newest first; a mob's remembered attackers are an `id_list`; aliases are a `std::list<alias_data>` with `std::string`s (`char_aliases()`). `clear_char()` and `clear_object()` assign a fresh value instead of `memset`ting, which would corrupt the containers. [Volund]
- `player_specials` is owned by its character (`owned<>`, `dbat/registry.hpp`: a `unique_ptr` that copies what it holds when copied), made with `char_make_player_specials()`; NPCs have none. A zone's reset commands are a `std::vector<reset_com>`, still ending with an `'S'`. [Volund]
- Saving a new mob or object in OLC no longer adds 1 to the mob and object numbers in shops, mobs and zone commands other builders have open: leftover renumbering from before prototypes were kept by vnum, which corrupted those numbers. The same dead code is gone from redit. [Volund]
- A connection's input queue is a `std::deque` of lines with `std::string` text, a player's communication history a `std::deque<std::string>` per channel (`char_comm_hist()`; freeing a character used to leak all but the first line of each), and the zone reset queue a `std::deque` of zone numbers. [Volund]
- The text editor works on a `std::string` the connection holds (`edit_text`), written back to where it goes (`d->str`, a `std::string *`) when it is saved. `string_edit_begin()` keeps what was there in `backstr`, a `std::string`, to put back if an OLC edit is aborted, so `string_write()` no longer takes a copy from each caller, and a backup left over from writing a note can no longer turn up as a character's description when that edit is aborted. [Volund]
- An object's name, descriptions and action description are `std::string`s, each object's own: the setters copy (`str_format()` and `take_string()` help callers that built a malloc'd string), the getters read null for an empty one as the files have it, and the pointer sharing with prototypes is gone for them (`obj_string_is_proto()` with it). Restringing no longer leaves an object sharing, and later reading after free, the strings its connection frees. [Volund]
- Extra descriptions are an `ex_desc_list` (`std::list<extra_descr_data>`, with `std::string` keyword and description), each object's and room's own: copying either copies them, and `copy_ex_descriptions()`, `free_ex_descriptions()`, `free_object_strings()` and `free_object_strings_proto()` are gone, as is the sharing of an object's extra descriptions with its prototype. `ex_desc_next()` and `ex_desc_remove()` serve the OLC menus. [Volund]
- A room's name and description are `std::string`s, as are an exit's keyword and description (read with `exit_keyword()` and `exit_description()`, null for none), and a room owns its exits (`owned<>`): `room_set_dir_option()` takes a new'd exit or null and frees the old one, so the hand-freeing of exits and their strings is gone, and copying a room copies its exits. [Volund]
- A character's name, descriptions, title, voice, roleplay display and feature, last user and party prompt are `std::string`s, as are a player's poofin, poofout, host and colour choices. The getters read null for an empty one (`c_str_or_null()`, `dbat/stringutils.hpp`) and the setters copy. Mobs no longer share strings with their prototypes, so `free_char()`, `free_mobile()` and the shutdown cleanup no longer free them by hand, OLC's `copy_mobile()` is a plain copy, and the mob transform no longer copies strings to keep from freeing the prototype's. A switched-into mob's prompt and a lockout no longer capitalise the character's own name in place. [Volund]
- A zone's name and builders are `std::string`s, as are a connection's account fields (user, email, password, character slots, the character being loaded), the restring fields, the news being written, its title and its command history (`std::string history[HISTORY_SIZE]`); `account_slot()` gives a `std::string *`. An empty one is what a null was. The unused `ship_name` is gone. [Volund]
- A shop's messages are `std::string`s, and what it sells, where it is and what it buys (with each type's keywords a `std::string`) are `std::vector`s rather than arrays ended by -1, so copying a shop is a plain copy: `free_shop()`, `free_shop_contents()` and the shop list helpers (`add_to_int_list()` and the rest) are gone. The getters `shop_get_product()`, `shop_get_room()` and `shop_get_buy_type()` give way to `shop_products()`, `shop_rooms()` and `shop_buy_types()`. [Volund]
- A guild's two messages are `std::string`s, so copying a guild is a plain copy and `free_guild()` and `free_guild_contents()` are gone. A guild being edited is now freed with its messages when the edit is saved. [Volund]
- A saved object with a negative unique id (other than -1, which means none yet) is given a new one, with a SYSERR, instead of being filed under a negative index in the unique id table. [Volund]
- A help keyword with an opening quote and no closing one no longer makes `one_word()` read past the end of the line, which could make the help table too small for what was loaded into it. [Volund]
- The text files the game shows (`motd`, `news`, `credits`, the greetings and the rest) are `std::string`s on `GameWorld`, empty for one that couldn't be read, and `free_text_files()` is gone. `newsedit` writes into the connection's own `draft` instead of borrowing `immlist` (the text of the immlist file, which no command shows), so an entry no longer starts out holding that file. [Volund]
- The configuration's text options (the OK, NOPERSON and NOEFFECT messages, the bind address, data directory and log file, the menu and the welcome and start messages) and the config file's path are `std::string`s, empty for one that isn't set, so copying the configuration copies them and `free_strings()` (`oasis_delete.cpp`) is gone. cedit's options find their fields with a small function each instead of `offsetof`, which isn't guaranteed to work on a struct holding `std::string`s. [Volund]
- A letter is written into the connection's `draft`, instead of a `char *` allocated for it and freed by hand wherever the writing ended. A board message's poster, subject and text, and a reader's name, are `std::string`s, a message's text empty until its author first saves it. OLC's `storage` (tedit's file, trigedit's script, the keyword or command hedit and aedit are adding) is a `std::string`, and trigedit compiles a copy of the script, where `strtok()` used to cut up the one being edited. `bad_data` now sends a letter and posts, aborts and answers on a board. [Volund]
- The help table is a `std::vector` of entries with `std::string` keywords and text, sorted with `std::stable_sort` (glibc's `qsort()` kept equal keywords in file order too), and `top_of_helpt` is gone. hedit's copy of the entry it edits is freed when the editor closes; it never was. [Volund]
- A trigger's name and argument list, each line of its script, and a mob's remembered command (`mremember`) are `std::string`s, so loading, copying, editing and freeing a trigger no longer duplicates or frees them by hand, and trigedit no longer leaks the old name or argument when one is changed. `str_str()`, `word_check()` and `is_substring()` take `const char *`. [Volund]
- A script variable's name and value are `std::string`s, so setting, removing and freeing variables no longer copies or frees them by hand. `remove_var()` takes a `const char *`. [Volund]
- DG script arithmetic (`eval` and `if`) wraps around when it overflows, as the game's builds did in practice, but now as defined behaviour, and dividing the smallest number by -1 wraps the same way where it used to make the processor trap and take the game down. [Volund]
- Script variable substitution (`var_subst()`) and the character, object and room fields it looks up build `std::string`s rather than writing into fixed buffers; a substituted line is still cut at `MAX_INPUT_LENGTH`, as the commands it goes to need. A script variable's value is capped at `MAX_DG_VAR_LENGTH`, the same length, with a SYSERR when something tries to set a longer one. `sprintbit()`, `sprinttype()` and `sprintbitarray()` have `std::string` versions. [Volund]
- A chained script field (`%x.y.z%`) no longer writes "tmpvr" over the variable's name in the line being substituted, which on a variable of one or two letters ran into the next field and looked up the wrong one. [Volund]
- DG script expressions are evaluated on `std::string`s: `eval_expr()` returns its result, `eval_op()` works on copies of its operands, and a script's lines are `const` while it runs, so matching a `case` no longer trims the spaces off the stored script line. The `char *` form of `var_subst()` is gone, and a `%variable` left open at the end of a line no longer makes it read past the line's end. [Volund]
- A script `wait` too long to count is held to `MAX_WAIT_PULSES`, as good as forever, where it used to overflow (in practice into no wait at all), and `wait until` with no time it can read is a script error rather than a wait until a time made of whatever was in memory. [Volund]
- A script message (`%send%`, `%echoaround%` and the like) ending in the escape character `\` ends there, where it used to read on past the end of the line. [Volund]
- A text field (`strlen`, `trim` and the rest) asked of something that isn't a variable, such as `%self.strlen%`, is looked for among that thing's own fields, where it used to crash the game. [Volund]
- An empty record in a shop file (a line with only `~`) is skipped with a SYSERR, where it used to crash the boot. [Volund]
- `dbat/args.hpp` takes a command's argument apart a word at a time from a `std::string_view`: `take_arg()`, `take_word()` and `take_quoted()` give what `one_argument()`, `any_one_arg()` and `one_word()` did, and `skip_spaces()` has a `string_view` form. `bad_data` checks them against the old functions on three thousand lines. [Volund]
- The lookups (`get_char_vis()`, `get_obj_in_list_vis()`, `get_obj_vis()`, the equipment ones, `get_player_vis()`, `get_char_room()`, `find_all_dots()` and `get_number()`) take the name as a `std::string &`, changing it as they always changed the caller's buffer (the `N.` taken off, a letter capitalised); their `char *` forms are kept for the commands not yet converted, and write back what was done. `generic_find()`, `find_eq_pos()`, `find_feat_num()`, `isname()`, `is_name()` and DG's `get_char()`/`get_obj()`/`get_room()` family take a `std::string_view`. `str_eq_nocase()`, `parse_int()` (what `atoi()` reads) and `string_view` forms of `is_abbrev()`, `is_number()`, `search_block()` and `CAP()` are in `dbat/stringutils.hpp`. `bad_data` checks the matching against the old code on twenty thousand pairs. [Volund]
- The attack commands (`commands/offense/` and `act.attack.cpp`) take their arguments apart with `dbat/args.hpp` into `std::string`s instead of fixed buffers, and `tech_handle_targeting()` and `tech_handle_charge()` take a `std::string &` and a `std::string_view`. [Volund]
- An object's spellbook pages are its own (`owned<>`), copied with it and freed with it: oedit's copy of a spellbook no longer shares the prototype's pages, which an edit changed at once even if it was then abandoned, and an editor closed on a spellbook no longer leaks them. `obj_make_sbinfo()` replaces `obj_sbinfo_slot()`. [Volund]
- The information commands (`commands/informative/`) take their arguments apart with `dbat/args.hpp`. `look_at_target()` takes a `std::string &`, `look_out_window()` and `find_exdesc()` a `std::string_view`, and `readUserIndex()` and `fingerUser()` a `const std::string &`; `users` parses its options from a view instead of copying the line into buffers. [Volund]
- The miscellaneous commands (`commands/misc/`) take their arguments apart with `dbat/args.hpp`. [Volund]
- The other commands (`commands/other/`) take their arguments apart with `dbat/args.hpp`. `mag_objectmagic()`, `list_skills()`, `print_skills_by_type()` and `race_find_form()` take a `std::string_view`, and `rpp_feature()` a `const std::string &`. [Volund]
- The wizard commands (`commands/wizard/`) take their arguments apart with `dbat/args.hpp`; `set` reads its target, field and value from one view instead of chopping a buffer four times. `find_target_room()` and the `vnum_*()` searches take a `std::string_view`. [Volund]
- The communication, social, item and movement commands (`act.comm.cpp`, `act.social.cpp`, `act.item.cpp`, `act.movement.cpp`) take their arguments apart with `dbat/args.hpp`. `AN()` is a function of a `std::string_view` rather than a macro, and `search_replace()` has a `std::string` version, which whispers that are overheard now use: the char * one built its result in a fixed buffer. [Volund]
- "get all.<thing> all.<container>" takes every <thing> from every container. Taking them from the first container stripped the "all." from the name, so from each of the others it took only one. [Volund]
- The OLC commands (`olc/`) take their arguments apart with `dbat/args.hpp`; `skillset` finds the quoted skill name in a view instead of lowercasing the line in place, and `dig` and `zedit new` read the rest of the line from the same view. [Volund]
- The mob and wizard script commands (`dg_mobcmd.cpp`, `dg_wizcmd.cpp`, and the object and room commands the converter could take) take their arguments apart with `dbat/args.hpp`. `find_obj_target_room()` takes a `std::string_view`. The object and room commands keep their `char *` lines for now. [Volund]
- `mjunk <name>` junks the item by that name and `mjunk all.<name>` every one by it. The first read a name after "all." from whatever it was given, so `mjunk sword` junked whatever matched "d" (and read past a name shorter than four letters); the second junked only one. `mjunk all` is as it was. [Volund]
- `mload mob <vnum> <room>` loads the mob into that room. The room came with the space before it, so it was never taken for a number and the mob was not loaded. [Volund]
- `mzoneecho`, `ozoneecho` and `wzoneecho` no longer overflow a buffer of `MAX_INPUT_LENGTH` with a message longer than that, which a script line can be once its variables are filled in. [Volund]
- `search_replace()` on a `std::string` with nothing to find changes nothing; `mechoaround` and `oechoaround` use it instead of copying the message into a buffer. [Volund]
- The special procedures, guilds and vehicles (`systems/`) take their arguments apart with `dbat/args.hpp`. The guild's practice, gain, forget, study and grand handlers take a `std::string_view`, and so do `rIntro()` and the vehicles' landing and boarding lookups. The shopkeeper's buy, sell, value, list and appraise still work on a `char *` line. [Volund]
- The house, ban, alias, disable and mail commands (`db/`) and the last of the wizard commands (`show`, `plist`, `load`, `findkey`, `echo`, `gecho`, `ginfo`, `poofset`, `newsedit`, `wiznet`) take their arguments apart with `dbat/args.hpp`. `find_alias()` takes a `std::string_view`, `delete_doubledollar()` has a `std::string` version, and `add_history()` takes a `const char *`. [Volund]
- An emote or smote of many `#`s no longer overflows the stack: each `#` became `$n` in place in a buffer of `MAX_INPUT_LENGTH`. The `std::string` `search_replace()` searches on from each replacement instead of from the start (what it finds is the same), so a long one takes no time. [Volund]
- `act()` stops at the end of its buffer: a message whose `$` codes expand past `MAX_STRING_LENGTH` (an emote of many `#`s, say) is cut short instead of overrunning the stack. [Volund]
- `wiznet` no longer leaks a copy of each line for each immortal who hears it. [Volund]
- Commands take their argument as a `std::string_view`: `ACMD`, `SPECIAL`, the command table's pointers, `command_interpreter()` and `special()` all do, so a command can no longer change the line it was given, and a caller with nothing to say passes "" rather than a null pointer. `writable{}` is gone, as are the `char *` lookups nothing calls any more; the DG message parser and the shopkeeper, which still take a `char *` line apart, keep the four they use, and the shopkeeper hands its buy, sell, value, list and appraise a copy of the line. The commands that use their argument as text (`say`, the gossip channels, `title`, `voice`, `help`, `assemble` and the like) work on a `std::string` of it, and `write_board_message()` takes a `std::string_view`. - The bot test's report keeps each log line whole: its standard output, which shares the report file with standard error, is line-buffered, so a line can no longer be split around another. [Volund]
- The printf-style output functions are renamed with a `_printf` ending (`send_to_char_printf()`, `write_to_output_printf()`, `mud_log_printf()`, `mudlog_printf()`, the `send_to_*_printf()` family, `send_to_imm_printf()`, `log_imm_action_printf()`, `script_log_printf()` and the DG `*_log_printf()`s, `str_format_printf()` and a few local ones), so that their `std::format` replacements can take the old names one directory at a time without an unconverted format string compiling against them. Nothing else changes. [Volund]
- `dbat/format.hpp` formats with `std::format`: `str_format()` checks its format when compiled and prints a null C string as "(null)", as printf did, and `as_unsigned()`, `as_char()` and `as_pointer()` read a value as printf's `%u`/`%x`/`%o`, `%c` and `%p` did. `send_to_char()`, `write_to_output()`, the `send_to_*()` family, `send_to_imm()`, `log_imm_action()`, `mud_log()`, `mudlog()` and `script_log()` are back under their names, taking either text as it is or a `std::format` string and its arguments; for now the rest go through their `_printf` versions. `tools/printf_to_format.py` converts calls (and checks its conversion against `snprintf()` for every conversion the code base uses), and the information commands (`commands/informative/`) are converted with it. A width or precision given at run time (`%-*s`, `%*d`, `%.*s`) becomes `printf_width()` or `printf_precision()` around the value, since clang can't check `std::format`'s own run-time widths against libstdc++ when compiling. The `std::format` functions that still pass their text to a `_printf` version call it as `(name_printf)(...)`, so that `tools/printf_to_format.py` leaves the call alone instead of turning it into one of themselves. [Volund]

- Everything else (`systems/`, `db/`, `net/`, `entities/`, `util/` and the tests) sends and logs its text with `std::format`: no call to a `_printf` function is left outside the functions themselves. `tools/printf_to_format.py` turns `%p` into `as_pointer()`, and world_audit's `problem()` takes a `std::format` string. [Volund]
- The boot log's `PCLEAN` lines show when each cleaned-out player last played. They showed the time of the boot instead: the date came from `asctime()`, whose buffer the logger's own `asctime()` call overwrote before printing it. [Volund]

[Volund]
- About 500 local `char` buffers filled with `snprintf()`, `sprintf()`, `strcpy()` or `strcat()` are `std::string`s, filled with `str_format()`, so text built in them is no longer cut short (`do_say()`'s ten-byte verb could overflow). `tools/printf_to_format.py --buffers` does the conversion, leaving and listing any buffer used in a way a string can't be. Identifying a scroll or potion with no spells no longer lists the item's flags as the spells it casts. [Volund]

Another 100 or so buffers are strings, the conversion now also taking one that is returned or declared with a comment after it. [Volund]

A buffer built with a length beside it (`len += snprintf(buf + len, sizeof(buf) - len, ...)`) is a string the conversion now takes too, as is one declared beside pointers; an integer precision (`%.3d`) is `printf_digits()` (`dbat/format.hpp`).
